# UX Research Skill

## Objective

Evaluate UX through **observable user behavior and evidence**, not aesthetic preference.

## Workflow

### 1. Define the user and task

Identify:
- target user;
- context;
- goal;
- task;
- constraints;
- expected frequency.

A design can be good for one task and poor for another.

### 2. Identify usability problems

Check:
- visibility of system status;
- match with real-world concepts;
- user control;
- consistency;
- error prevention;
- recognition vs recall;
- flexibility;
- minimalist presentation;
- error recovery;
- help/documentation.

### 3. Cognitive analysis

Consider:
- cognitive load;
- working memory;
- decision complexity;
- choice overload;
- visual hierarchy;
- information scent;
- progressive disclosure;
- recognition vs recall;
- attention;
- error likelihood.

### 4. Visual and interaction analysis

Evaluate:
- hierarchy;
- spacing;
- typography;
- contrast;
- alignment;
- affordances;
- feedback;
- navigation;
- interaction consistency;
- responsive behavior;
- accessibility.

Do not criticize visual style merely because it differs from personal taste.

### 5. User research

When research data exists, analyze:
- interviews;
- usability tests;
- surveys;
- SUS;
- task completion;
- time on task;
- error rate;
- abandonment;
- qualitative themes.

Distinguish observed behavior from stated preference.

### 6. Quantitative UX

When screenshots or measurements are available, consider relevant metrics such as:
- edge density;
- feature congestion;
- visual complexity;
- entropy;
- task completion;
- SUS;
- NASA-TLX.

Do not pretend a metric proves usability by itself.

### 7. Recommendations

Every recommendation should specify:

**Problem → Evidence → User impact → Proposed change → Expected outcome → Validation method**

Prioritize:
- severity;
- frequency;
- business/user impact;
- effort.

## Output

1. Executive UX assessment
2. User/task assumptions
3. Major usability issues
4. Cognitive load
5. Information architecture
6. Visual/interaction analysis
7. Accessibility
8. Evidence
9. Prioritized recommendations
10. Validation plan

## Research discipline

If only a screenshot is provided:
- evaluate observable interface characteristics;
- clearly label inferred user problems as hypotheses;
- do not claim that users actually experienced an issue without user evidence.

If user research is provided:
- ground conclusions in the data.
